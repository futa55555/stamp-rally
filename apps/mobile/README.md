# Stamp Rally mobile

Expo SDK 57 / React Native 0.86。NativeWind 4.2 / Tailwind CSS 3.4、React Native 標準コンポーネントと MaterialCommunityIcons を使った、旅行の写真を共有するアプリのモックです。

## 起動・検証

```sh
pnpm install
pnpm --filter mobile ios
pnpm --filter mobile android
pnpm --filter mobile typecheck
pnpm --filter mobile test
pnpm exec oxlint apps/mobile
pnpm exec prettier --check apps/mobile/src apps/mobile/*.ts apps/mobile/*.js apps/mobile/*.css apps/mobile/*.json apps/mobile/README.md
pnpm --filter mobile exec expo export --platform ios --platform android
```

Google / Apple のどちらからもサンプルアカウントで入れます。実際の認証やAPI通信は行いません。変更はメモリに保持され、ログアウト後の再ログインでは残りますが、アプリの再起動・開発中のリロードではリセットされます。サンプル写真は同梱されています。

## 構成

- `src/app/`：Expo Router のルートとレイアウト。通常のルートは `pages/` の画面を再exportし、共通編集画面には種類を渡します。`Stack.Protected` による認証分岐、Providerの組み立て、NativeTabs・Stackの設定もここに置きます。
- `src/pages/`：各画面の実装の正本。画面専用のまとまりは各pageの `sections/`・`components/` に置きます。旅行・ジャンル・スタンプの編集は `entity-editor/` の共通実装です。
- `src/features/`：ドメインの型・検証・整形・取得フック・画面をまたぐ機能UI。`trips/` は旅行・ジャンル・スタンプをまとめて扱い、`photos/` は写真・お気に入り・既読・写真選択、`notifications/` は通知、`auth/` は認証・ユーザー情報、`editor/` は編集・投稿フローを扱います。
- `src/features/app-data/`：複数ドメインを束ねる単一のContext / Reducer、`api/DataService.ts` のサービス契約、`mocks/` のモックとfixtures。`AppDataProvider` に別のサービスを渡して差し替えられます。横断する更新・動作のテストもここに置きます。
- `src/shared/`：ドメインに依存しない共通処理。`ui/` は標準の View / Text / Pressable などを使ったUI、`theme/` はThemeProviderとトークン、`hooks/` は汎用フック、`lib/` は日付・ソートなど、`navigation/` は共通ヘッダーの設定です。配色は `theme/tokens.ts` に集約し、通常のUIは `className` を使い、Tailwind設定から共通の配色・文字トークンを参照します。ネイティブAPIや外部ライブラリの設定値には `useAppTheme()` を使用します。
- `assets/`：`src/` と同階層に置く同梱画像・画像URL定数・静的参照マップ。画面からは `PhotoImage` を通して画像を表示します。

UIは使用回数だけで判断せず、ドメインへの結びつきと画面固有の構成かどうかで配置します。写真へのお気に入り操作を持つ `PhotoTile` は `features/photos/ui/`、旅行一覧専用の `TripCard` は `pages/trip-list/components/`、画像の表示・読み込み・再試行を扱う `PhotoImage` は `shared/ui/` に置きます。

依存は基本的に `app → pages → features → shared` です。appからProviderなどのfeatures利用と、feature間の参照は許可します。featuresからpages、sharedからfeaturesへの参照は作りません。通知と投稿完了で共用する遷移先解決は `features/trips/navigation/` に置きます。app-dataから呼ぶモデル・純粋関数はProviderに依存させず、型の参照と実行時の依存を分けます。importは具体的なモジュールへの相対パスを使用します。

タブバーは `expo-router/unstable-native-tabs` の OS ネイティブUIです。アイコンは `NativeTabs.Trigger.VectorIcon` を通して MaterialCommunityIcons を使用し、ラベル・アイコン・選択背景・未読バッジの色もテーマトークンから指定します。

旅行一覧は「旅行中 → Hero → あなたの旅行」の順です。端末の暦日で開始日・終了日当日を含めて旅行中と判定し、開始日降順で並べます。「あなたの旅行」は作成ボタン → これからの旅行 → 過去の旅行。未来は開始日昇順・同日なら終了日昇順、過去は終了日降順・同日なら開始日降順です。同じ日程は作成日時降順・ID降順で安定させます。空の分類は見出しごと省略し、旅行0件でもHeroと作成ボタンは表示します。

本文は左右16（`px-4`）、セクション間は24（`gap-6`）が基本です。Metroの `inlineRem: 16` により1remを16に揃えます。旅行のカバー、お気に入りの横スクロール、投稿グリッドは画面幅を使います。スクロール内容と列間隔は `contentContainerClassName` / `columnWrapperClassName` で指定します。ヘッダーは共通枠を使う `TopHeader` / `PageHeader` / `FormHeader` の3種類で、文字拡大を有効にし、タイトルの全文を読み上げに渡します。

ジャンルのスタンプと投稿写真は2列で、端数も左詰め・同じ列幅です。お気に入りカードとスタンプカードの画像は角丸、投稿写真は隙間・角丸なしで表示します。スタンプの代表画像はお気に入り優先でランダム選択し、候補がなければ全画像投稿から選びます。画面のマウント・候補集合の変更時だけ再抽選し、通常の再描画やスクロールでは保持します。お気に入りは共有・複数枚。写真の既読は自分以外の写真が PhotoDetail で読み込みに成功し、画面がフォーカスされたときに更新します。通知の既読とは独立しています。

名前はtrim後1〜20文字、サンプルユーザー間で一意です。動画・既存投稿の編集・削除・招待・コメント・プッシュ通知・端末保存は対象外です。UI文言は日本語、テーマはライトのみです。

## 作成・編集・投稿

- 旅行一覧から旅行を作成できます。作成者が参加者になります。
- 旅行・ジャンル・スタンプ詳細の本文タイトル横にある「編集」から編集できます。ジャンル／スタンプの作成は親画面の見出しの「＋」と空状態のボタンから行います。
- 各詳細画面のヘッダー右上のカメラアイコンから、開いている旅行・ジャンル・スタンプを引き継ぎます。Native Tabsの上に固定フッターは置きません。投稿画面ではすべて変更でき、上位項目を変更すると下位項目を選び直します。
- 旅行一覧・お知らせ・設定のトップヘッダーは「Stamp Rally」とカメラアイコンを表示し、投稿先未選択で投稿を開きます。詳細の戻るラベルは旅行なら「一覧」、ジャンルなら親旅行名、スタンプなら親ジャンル名で、戻り先と一致します。
- 投稿先の選択画面からジャンル／スタンプを新規作成できます。作成後は写真を保持して投稿へ戻ります。作成済みの項目は投稿をキャンセルしても残ります。
- 写真ライブラリからの複数選択とカメラ撮影に対応します。1回につき最大10枚、写真1枚につき1投稿です。選択後は拡大・追加・選択解除ができます。
- 投稿後は対象スタンプを開き、戻るとそのジャンル・旅行に移動します。達成状態・写真件数は親階層まで更新されます。
- 旅行は名前・日程・任意の行き先リスト・任意のカバー画像、ジャンル／スタンプは名前・任意の説明を編集できます。名前はtrim後1〜100文字、説明は2,000文字までです。
- フォームは×で呼び出し元に戻ります。
- 未保存の変更は閉じる際に破棄確認を行います。保存失敗時は入力を保持し、保存中の二重操作は防ぎます。

日程欄を押すと直下に `react-native-calendars` の月間カレンダーを1つ表示します。開始日→終了日の順に選ぶと確定して閉じ、同日も選べます。開始日より前を押すと開始日を選び直します。途中で閉じた場合は確定済みの日程を保持します。新規旅行の初期値は今日〜今日です。

行き先は手動で追加・編集・削除でき、保存時に前後空白と空項目を除き、入力順を保持します。旧データで `locations` がない場合は空配列として扱い、表示は「未設定」です。参加者は既存のユーザー・参加情報から表示します。

カバー欄は `@expo/react-native-action-sheet` で「ライブラリから選ぶ／撮影する／キャンセル」を表示します（iOSは標準Action Sheet、Androidはボトムシート）。写真選択・撮影は `expo-image-picker` を再利用し、キャンセル時は元の画像を保持します。画像解除、権限拒否時のエラー・設定への導線、再試行に対応します。独自の開発ビルドを使っている場合、依存と権限設定の追加を反映するため再ビルドしてください（`pnpm --filter mobile exec expo run:ios` / `expo run:android`）。iOSシミュレーターではカメラ撮影を利用できないため、撮影は実機で確認します。

自動テストは旅行分類・並べ替え・境界日、期間選択、行き先の保存・更新・旧データ、代表画像の候補と保持、既存のお気に入り・既読・投稿フローを対象にしています。

## 手動確認

1. ログイン → 旅行 → ジャンル → スタンプ → 写真の順に移動し、戻る。お気に入り一覧からの写真表示も確認する。
2. 京都の「朝のまちを歩く」の未読写真（あおい）を開き、ジャンル・スタンプのバッジが消えることを確認する。
3. 投稿グリッド右上のハートを操作し、旅行のお気に入り一覧・ジャンルの代表画像候補に反映されることを確認する。サムネイルの表示だけでは未読が消えず、写真詳細を開くと既読になることを確認する。写真詳細の既存の星操作も維持しています。
4. お知らせから写真・スタンプ・旅行・ジャンルへ移動し、戻ると同じ旅行の親画面になることを確認する。
5. 設定で名前変更・空文字や重複名のエラー・キャンセル・キーボードを確認する。ログアウト後、戻る操作で Main に戻れないことを確認する。
6. iOS・Androidの小さい画面とタブレット、文字拡大、長い名前で、ヘッダーの高さ・中央配置・末尾省略、未読バッジ、2列グリッドの端数、全幅画像、画像読み込み失敗を確認する。

7. 新しい旅行 → ジャンル → スタンプを作成し、写真を複数投稿する。写真一覧、達成率、お気に入り、戻る順序を確認する。
8. 旅行／ジャンル／スタンプの各入口で投稿先の初期値を確認する。写真を選んで旅行・ジャンルを変更し、下位だけがリセットされることを確認する。
9. 写真を選択後、投稿先の選択から新しいジャンル／スタンプを作る。作成項目の自動選択と写真の保持を確認する。
10. 各種編集の反映、カバー画像の変更・解除・キャンセル、名前と説明の文字数、行き先の追加・編集・削除を確認する。カレンダーは同日・逆順・月年またぎ・途中で閉じる操作を確認する。
11. 写真の選択キャンセル・10枚上限・拡大・解除、カメラ権限拒否・再試行、保存連打、戻る際の破棄確認を確認する。

## 写真

`assets/demo` は [Unsplash](https://unsplash.com/license) のサンプル写真です。元の画像URLは `assets/demoPhotoUrls.ts`、同梱画像への対応は `assets/photoSources.ts` に記録しています。画面の旅行名や投稿者は架空で、写真はイメージです。
