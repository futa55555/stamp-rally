# 旅行編集・削除の仕様

UIは「カテゴリー」「スタンプ」を使います。API・DB・型もCategory/categoriesに統一し、旧genre APIは提供しません。マイグレーション後はAPI・media worker・mobileを揃えて更新してください。

## 削除と復元

| 操作             | DB                                           | 投稿・R2                                                                           |
| ---------------- | -------------------------------------------- | ---------------------------------------------------------------------------------- |
| 投稿を削除       | deleted_atを設定                             | 30×24時間復元可能。メディアを保持                                                  |
| 投稿の期限切れ   | deleted_atを保持しpurged_atを設定            | 復元不可。R2清掃を予約                                                             |
| スタンプを削除   | deleted_atを設定、全カテゴリーから解除       | ゴミ箱・アップロード中も含む全投稿を復元不可にする                                 |
| カテゴリーを削除 | deleted_atを設定、所属を解除                 | 他の有効なカテゴリーにも属するスタンプ・投稿は保持。最後の所属を失うものを永久削除 |
| 旅行を削除       | 旅行・カテゴリー・スタンプにdeleted_atを設定 | 全投稿を復元不可にし、カバーを清掃。招待を無効化                                   |

Trip/Category/Stamp/Postの行は永久削除後も残ります。purged_atは「復元不可になった時刻」です。原本・派生画像・再生動画・staging・multipartの清掃予約を同じDBトランザクションで記録し、20分後からworkerがR2を清掃します。失敗は再試行します。詳細は [media-uploads.md](media-uploads.md) を参照してください。

参加者全員が削除・復元できます。設定のゴミ箱は旅行名・旅行期間でまとめ、投稿のスタンプ名と復元期限を表示します。ゴミ箱から手動で永久削除するUIや一括操作はありません。

## テンプレート編集

- 場所・やりたいことを外すと、その由来だけを外します。別の由来が残るテンプレートや手動追加の項目を保持します。
- 投稿、復元可能なゴミ箱、アップロード中・処理中・失敗した投稿がある項目は、自動で外しません。必要なカテゴリーも保持します。
- 由来をすべて外した後に明示的に選び直したスタンプは、手動の選択として保持します。
- チェックボックスの手動解除は所属の解除です。最後の所属を失うスタンプと投稿は永久削除になります。確認ダイアログで削除範囲と復元不可を明記します。
- 選択変更は保存まで下書きです。キャンセルや通信失敗で保存しません。手動で外した選択は次回編集にも反映し、削除後の再追加では新しい行を作ります。
- 既存データを名前でテンプレートに結び直しません。新規のテンプレートだけに固定IDと由来を記録し、名称変更でも同一性を維持します。

## API

`POST /trips/:id/template-preview`（200）は `locations?`、`activityPresets?`、`changes?` を受け、既存項目と候補の選択状態、保護理由、永久削除となるスタンプ数・投稿数、confirmationTokenを返します。DBを変更しません。

changesは操作順の `{ categoryRef, stampRef?, selected }[]` です。refはレスポンスから受け取り、既存行はUUID、新規候補はtemplate keyを使用します。stampRef省略でカテゴリー内の選択をまとめて変更します。

`PATCH /trips/:id` は旅行情報に加えてactivityPresets・customActivities・templateEditを受け取ります。templateEditは `{ clientRequestId, changes, confirmationToken? }` です。clientRequestIdは保存操作のUUIDで、応答を失った再試行は同じID・同じ入力を送ります。保存済みのIDを別の入力に使うと409になります。

保存時にserializable transactionで再計算します。自動解除の対象に新しく投稿された場合は項目を保持します。手動の永久削除対象が確認時と変わった場合は、`TEMPLATE_IMPACT_CHANGED`（409）と最新previewを返し、すべての変更をロールバックします。mobileは次の保存で最新内容を取得して再確認します。

マイグレーションは既存行を手動扱いにし、名前でテンプレートIDを埋めません。PostgreSQLで、由来の保持、共有所属、期限境界、同時アップロード、確認後の新規投稿、応答再試行、R2清掃の失敗と再試行を検証しています。
